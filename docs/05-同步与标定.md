# 05 · 同步与标定

## 1. 双机同步方式

- 同步类型：**主机时钟近同步**（host_clock_near_sync）。
- 含义：两台相机各自以 SDK 方式取流，由采集主机按接收顺序把每台相机的帧**一一配对**（每对一帧），同时记录主机时间戳与设备时间戳。
- **不是**硬件触发严格同步，因此帧与帧之间存在毫秒级偏差；跨相机融合必须参考审计数据。

### 1.1 时间审计字段

capture_manifest.json → sync_audit：

| 字段 | 说明 |
| --- | --- |
| synchronization_kind | 固定 `host_clock_near_sync` |
| pair_count | 配对帧数，恒为 5 |
| max_host_timestamp_skew_ms | 本会话 5 对中最大的主机时间戳偏差 |
| pairs[].host_timestamp_skew_ms | 单对主机时间戳偏差（毫秒） |
| pairs[].request_start_skew_ms | 单对取帧发起时刻的偏差（毫秒） |
| pairs[].gemini_host_timestamp_ns / d435i_host_timestamp_ns | 两台相机的主机接收时间戳（纳秒） |
| pairs[].gemini_device_timestamp / d435i_device_timestamp | 两台相机的设备时间戳 |
| pairs[].gemini_frame_number / d435i_frame_number | 两台相机的帧计数 |

同源信息亦汇总到受试者清单：angles.<Vxxx>.attempts[].max_host_timestamp_skew_ms。

### 1.2 全库时间偏差实测分布（664 个会话）

| 指标 | 数值 |
| --- | --- |
| 配对帧数 | 每会话恒为 5（664/664） |
| 最大主机时间戳偏差 · 最小值 | 9.00 ms |
| 最大主机时间戳偏差 · 均值 | 19.40 ms |
| 最大主机时间戳偏差 · 最大值 | 73.86 ms |
| 取帧发起时刻偏差 · 范围 | 0 – 94 ms |

结论：双机时间关系稳定在**数十毫秒**量级，适合做静态人体姿态与体型分析；对快速运动场景需按对做重采样或时间对齐。

## 2. 标定信息

标定数据**逐帧携带**（storage_features 中的 per_frame_calibration_v1），即每一帧都附有当时生效的内外参，而不是全库共用一套。

### 2.1 内参（每帧三套）

| 相机 | 彩色 | 原始深度 | 对齐深度 |
| --- | --- | --- | --- |
| C336L | 1280×720，畸变模型 orbbec（8 系数） | 848×480，畸变模型 orbbec（8 系数） | 1280×720，与彩色同参 |
| CD435I | 1280×720，distortion.inverse_brown_conrady（5 系数） | 1280×720，distortion.brown_conrady（5 系数） | 1280×720，与彩色同参 |

字段：fx、fy、cx、cy、width、height、distortion_model、coefficients[]。
注意：两台相机的畸变模型与系数长度不同（orbbec 8 系数 vs Brown-Conrady 5 系数），去畸变实现不可混用。

### 2.2 外参

| 相机 | 提供的外参 | 平移单位 |
| --- | --- | --- |
| C336L | depth_raw_to_color | **毫米** |
| CD435I | depth_raw_to_color、color_to_depth_raw | **米** |

**这是最容易踩的坑**：同样名为 translation 的字段，两台相机的单位不同，融合前必须统一。

### 2.3 对齐语义

- depth_aligned 的坐标系为**彩色相机坐标系**，且与彩色图像素一一对应（对齐后内参与彩色内参一致）。
- depth_raw 的坐标系为**深度相机原生坐标系**，未对齐。
- 点云坐标单位统一为**毫米**，按每 4 像素取 1 点生成。

### 2.4 深度比例

| 相机 | depth_scale_mm_per_unit |
| --- | --- |
| C336L | 1.0 |
| CD435I | 1.0000000474974513 |

该值在 664 个会话的 6,640 个深度文件条目中完全一致，但仍应逐帧读取而非硬编码。

## 3. 单机内的时序契约

capture_manifest.json → frames.<camera_code>[i].camera_metadata.frame_contract：

| 字段 | 含义 |
| --- | --- |
| spatial_alignment.depth_aligned_matches_rgb_pixels | 对齐深度与彩色像素一一对应 |
| spatial_alignment.aligned_intrinsics_match_rgb | 对齐深度内参与彩色一致 |
| spatial_alignment.raw_to_color_extrinsics_present | 提供原生深度到彩色的外参 |
| temporal_alignment.source | 同一 SDK frameset（CD435I 单机内三流同源） |
| temporal_alignment.stream_timestamp_skew_ms / maximum_allowed_ms | 单机内三流时间戳偏差及其上限 |
| temporal_alignment.raw_aligned_depth_frame_number_equal | 原始与对齐深度帧号一致 |

## 4. 设备与码流（型号级，全库一致 664/664）

| 项目 | C336L | CD435I |
| --- | --- | --- |
| 型号 | Orbbec Gemini 336L | Intel RealSense D435I |
| 接口 | USB 2.1 | USB 3.2 |
| 固件 | 1.6.00 | 5.15.1.55 |
| SDK | pyorbbecsdk 2.1.1 | pyrealsense2 2.54.2.5684 |
| 彩色流 | 1280×720 @10fps，MJPG | 1280×720 @30fps，rgb8 |
| 原始深度流 | 848×480 @10fps，Y16 | 1280×720 @30fps，z16 |
| 对齐深度流 | 对齐到彩色，1280×720 | 对齐到彩色，1280×720 |
| 时间戳来源 | 设备流时间戳 | 彩色流为主时钟 |
| 红外流 | 不提供（采集端不伪造缺失模态） | 未采集 |

全库仅使用**同一对物理设备**（序列号/UID 等唯一标识不公开），因此设备固件与 SDK 版本在整个数据集中保持一致，不存在跨设备版本漂移。
